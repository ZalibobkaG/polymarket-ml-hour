# Установка бота (один раз)

Этот документ — для того, кто ставит и запускает бота, но не писал его код и
не обязан разбираться в логике торговли. Всё по шагам: что делать, что должно
получиться, что делать, если получилось не то.

Когда дойдёте до конца — переходите к [НАПАРНИК_ПРОГОН.md](НАПАРНИК_ПРОГОН.md).

---

## 1. Что это

Бот раз в час ставит на направление часовой свечи BTC на Polymarket. Сторона
(вверх или вниз) приходит от модели за 2 минуты до начала часа, заявка
кладётся лимиткой по цене **0.51**; если к 12-й минуте часа она не
исполнилась — бот добирает недостающее по рынку, но не дороже **0.55**.
Размер одной ставки — **10 шейров** (около 5.10$ под риском на час).

Управлять ботом на ходу можно из Telegram — команды описаны во втором
документе.

## 2. Установка

### 2.1. Python

Нужен **Python 3.11 или новее**. Это не прихоть: в `settings.py` используется
`tomllib` — модуль разбора TOML, который появился в стандартной библиотеке
Python именно в версии 3.11 (для более старых версий в коде есть запасной
разбор, но проверялся он не так тщательно, поэтому рисковать не стоит).

Проверить версию:

```bash
python --version
```

**Должно получиться:** `Python 3.11.x` или новее.
**Если не то:** версия ниже 3.11 или команда `python` не найдена — поставьте
Python 3.11+ с [python.org](https://www.python.org/downloads/) (на Windows
при установке обязательно отметьте галочку «Add python.exe to PATH»).

### 2.2. Какая копия — боевая

На этой машине репозиторий бота может лежать в нескольких местах — так уже
получилось исторически, и это не ошибка, а рабочее состояние. **Боевая
копия — ровно одна**, у неё это написано прямо в шапке `README.md`:

> Это боевая копия (ветка `execution-limit051-cross`). Остальные локальные
> копии — устаревшие, не запускать.

Правило простое: открываете папку, смотрите первую строку `README.md`. Если
там нет фразы «боевая копия» — это не та папка, закрывайте её и ищите
другую. Все команды в обоих документах выполняются **из папки боевой
копии** — откройте в ней терминал.

### 2.3. Убедиться, что взята именно нужная ветка

Внутри папки боевой копии выполните:

```bash
git branch --show-current
```

**Должно получиться:** ровно одна строка — `execution-limit051-cross`.

**Если не то:**
- напечаталось `main` или любое другое имя — это не боевая ветка, работать в
  этой папке нельзя; сообщите владельцу и не запускайте бота, пока не
  разберётесь;
- команда выдала ошибку «not a git repository» — вы не в папке репозитория,
  поднимитесь/спуститесь по каталогам до папки, где лежит `main.py` и
  `README.md`, и повторите.

### 2.4. Зависимости

Из папки боевой копии:

```bash
python -m venv .venv
```

Дальше — активировать окружение и поставить зависимости. Команда отличается
по системе:

**Windows (PowerShell):**
```powershell
.venv\Scripts\pip install -r requirements.txt
```

**Linux / macOS:**
```bash
.venv/bin/pip install -r requirements.txt
```

**Должно получиться:** в конце вывода строка вида `Successfully installed …`
со списком пакетов, без слова `ERROR`.

**Если не то:**
- `ERROR: Could not find a version that satisfies the requirement lightgbm==4.5.0`
  — проверьте версию Python ещё раз (см. 2.1), для некоторых версий Python
  колёса `lightgbm==4.5.0` не собраны;
- любая другая ошибка сети/пакета — повторите команду ещё раз (иногда это
  временный сбой PyPI); если повторяется — пришлите текст ошибки владельцу.

Окружение весит около 500 МБ (в основном `pyarrow` и `pandas`) — это
нормально, см. `README.md`, раздел «Развёртывание на сервере».

## 3. Ключи (`.env`)

Файл `.env` **заполняет владелец бота, не напарник**. Ваша задача на этом
шаге — только убедиться, что файл на месте (см. `python main.py doctor` в
разделе 4) и что вы не пытаетесь вписывать туда ключи сами.

Файла `.env` нет в git — он создаётся из примера `.env.example` и живёт
только на конкретной машине. В нём ровно восемь переменных:

| Переменная | Что это и откуда берётся |
|---|---|
| `POLY_PRIVATE_KEY` | Приватный ключ торгового кошелька Polymarket. В MetaMask: три точки у аккаунта → Account details → Show private key. |
| `POLY_FUNDER` | Proxy-адрес аккаунта Polymarket — тот, на котором лежат деньги, из URL профиля на polymarket.com. **Это не адрес MetaMask.** |
| `POLY_SIGNATURE_TYPE` | Тип подписи ордеров: `3` — депозитный кошелёк (POLY_1271), `2` — MetaMask/Safe, `1` — email/Magic, `0` — обычный EOA-кошелёк. Зависит от того, как создавался аккаунт на Polymarket; неверный тип сразу видно по `python main.py check` — баланс покажет 0.00$ при непустом счёте. |
| `POLY_API_KEY` | API-ключ CLOB. Можно оставить пустым — выводится из приватного ключа автоматически. |
| `POLY_API_SECRET` | API-секрет CLOB. Можно оставить пустым — выводится автоматически. |
| `POLY_API_PASSPHRASE` | API-пароль CLOB. Можно оставить пустым — выводится автоматически. Без всех трёх L2-кредов не работает только WebSocket-канал своих сделок; сама торговля идёт и без него, через опрос биржи раз в 30 секунд. |
| `TG_TOKEN` | Токен Telegram-бота. Получается при создании бота через `@BotFather` в Telegram — это общий способ Telegram, не особенность этого проекта. |
| `TG_ALLOWED_USER_IDS` | Числовые id пользователей Telegram через запятую — кому можно управлять ботом; уведомления уходят первому в списке. Свой числовой id можно узнать, например, написав боту `@userinfobot`. |

Значений и примеров ключей здесь намеренно нет — их вписывает только
владелец.

**Ключи нельзя пересылать никому и никуда — ни в переписке (включая
Telegram, почту, мессенджеры), ни сохранять в облако.** Ключ, который хоть
раз попал в чат, архив или скриншот, считается скомпрометированным и
подлежит немедленной замене — даже если переписка потом удалена.

## 4. `python main.py doctor`

Эта команда ничего не торгует и не запускает — только проверяет готовность.
Выполните из папки боевой копии:

```bash
python main.py doctor
```

(на Windows, если venv не активирован в терминале: `.venv\Scripts\python main.py doctor`)

Выводит девять пронумерованных проверок. Разбор каждой:

**1. Переменные окружения** — сверяет `.env` со списком из восьми переменных
(раздел 3), печатает «заполнено»/«пусто» по каждой, ни один ключ целиком не
показывает.
Провал: файла `.env` нет вовсе → скопируйте `.env.example` в `.env` и
передайте владельцу на заполнение; либо `DRY_RUN=False` (боевой режим), а
`POLY_PRIVATE_KEY` пуст → без него в боевом режиме бот не запустится, нужно
либо получить ключ от владельца, либо оставить `DRY_RUN=True`.

**2. Доступность CLOB_HOST и GAMMA_HOST** — проверяет связь с двумя серверами
Polymarket, печатает код ответа и время в мс.
«не проверено» (не провал) — нет интернета: проверьте сеть на машине.
Провал — сервер ответил кодом 500+: сервис Polymarket сейчас недоступен,
подождите и повторите позже, это не поломка бота.

**3. Ближайший часовой рынок** — ищет рынок BTC Up/Down, который откроется
следующим, показывает его слаг, бид/аск и шаг цены.
«не проверено» — нет сети (см. пункт 2).
Провал — рынок не найден или помечен как не принимающий заявки: сообщите
владельцу, это может значить, что Polymarket поменял правила рынка.

**4. Комплект модели** — проверяет, что все файлы модели (`poly_hourly_kit/`)
на месте, контрольные суммы совпадают, и делает тестовый прогноз на
зашитых в комплект данных (без сети).
Провал — не хватает файлов, модель не загрузилась или прогноз вне диапазона
0..1: комплект модели повреждён или неполный — восстановите его из бэкапа
репозитория и не запускайте бота до исправления, это не тот случай, который
чинится вручную на глаз.

**5. Расхождение часов с биржей** — сравнивает системное время машины со
временем сервера Polymarket (из заголовка HTTP-ответа), порог — 5 секунд.
«не проверено» — нет ответа сервера (см. пункт 2).
Провал — часы разошлись больше чем на 5 секунд: решение о ставке
принимается ровно за 2 минуты до часа, неточные часы собьют этот момент.
Синхронизируйте время: Windows → Параметры → Время и язык → Синхронизировать
сейчас.

**6. База `data/bot.db`** — создаёт (если нет) и проверяет, что в базу можно
писать, миграции прошли.
Провал — база не пишется (нет прав на папку, диск занят и т.п.): проверьте
права доступа к папке `data/` и свободное место на диске.

**7. Telegram** — если `TG_TOKEN`/`TG_ALLOWED_USER_IDS` заполнены, проверяет
токен (`getMe`) и что бот может писать получателю (`getChat`).
Провал «не настроен» — переменные пустые: это осознанный выбор или
недосмотр владельца, уточните у него.
Провал «токен не работает» — токен неверный, попросите владельца проверить
`TG_TOKEN`.
Провал «получатель ещё не открыл бота и не нажал Start» — получателю нужно
самому написать что угодно боту в Telegram один раз, иначе бот не может
написать первым.
«не проверено» — нет сети.

**8. `settings.toml`** — если файл есть, проверяет допустимость значений и
печатает, какие параметры переопределены (а какие — по умолчанию из
`config.py`).
Провал — в файле опечатка, неизвестный ключ или значение вне допустимого
диапазона: текст ошибки называет конкретный параметр и что с ним не так,
поправьте `settings.toml` по этому тексту (см. раздел 7 второго документа —
что вообще можно там менять).

**9. РЕЖИМ РАБОТЫ** — не проверка, а информационная сводка: показывает,
бумажный сейчас режим или боевой (`DRY_RUN`), и включена ли торговля вообще
(`TRADING_ENABLED`). Смотрите на неё каждый раз перед запуском — раздел 1
второго документа объясняет, что здесь должно быть видно на время прогона.

Если хотя бы одна из проверок 1–8 провалилась, в конце будет список
«ПРОБЛЕМЫ» и код возврата 1 — бота запускать нельзя, пока список не станет
пустым. «Не проверено» само по себе провалом не считается (обычно значит
«нет сети прямо сейчас»), но если это единственная причина странного
поведения — стоит попробовать ещё раз, когда сеть появится.
